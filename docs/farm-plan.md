# 데일리 농장: 홈(프로필) 카드 왼쪽 농사 게임

## Context
허브는 `홈 · 스도쿠 · 삼각관계 · 워드십 · 흑백 지뢰찾기` 카드를 좌우로 넘기는 정적 사이트다(GitHub Pages, 저장은 전부 localStorage). 데일리를 매일 하게 만드는 장치로, 홈 **왼쪽**에 한 달 시즌제 농사 게임 카드를 붙인다. 출석과 데일리 결과로 NP를 모으고, 게임 흐름은 탐험 → 농사/제작 → 요리 → 도감 등록(시즌 퀘스트)이다.

기획은 사용자가 항목마다 직접 정하고, Claude는 받은 대로 정리하면서 요청받은 부분(작물 이름, 제작 비용)만 추천했다. 모든 숫자는 구현할 때 `farm/data.js` 한곳에 모으고, 같은 내용을 `docs/farm-plan.md`(이 문서)와 `docs/farm-GDD.xlsx`에 둔다.

## 확정 규칙

### 1. 기호
- `now` = `Date.now()` (ms), `h` = 3,600,000 ms
- `today` = `todayStr()` (index.html, KST 06:00 경계), `season` = `today.slice(0, 7)` (예: `2026-10`)
- 품질은 **정수 1~100**

### 2. NP
```
np(r)   = r 없음 → 0 · r.status === 'solved' → 3 · 그 밖(실패·시간 초과·포기) → 2
earned  = Σ_{d: d가 season 달, d ≤ today} [ 5·출석(d) + Σ_{게임 × 모드} np(results[d]) ]
balance = earned + bonus − spent
```
- `results` = 각 게임 `statsKey(mode)`의 `results`. 지난 퍼즐·자유 연습은 원래 기록되지 않는다. 게임×모드는 스도쿠 2 · 삼각관계 2 · 워드십 3 · 흑백 지뢰찾기 2로 **9개**
- 출석(d) = 그날 허브를 열었으면 1 (`refreshStatus` 때 `today`를 `attendance`에 추가)
- `bonus` = 보물 상자에서 나온 NP. `spent` = 상점에서 쓴 NP(§15 NP 상점). 둘 다 저장하고 시즌마다 초기화. `earned`는 저장하지 않고 매번 계산
- 출석·플레이로 하루 최대 5 + 9×3 = **32**, 시즌(31일) 최대 **992**
- 화면에서 NP를 누르면 내역이 나온다: 출석 n일 · 성공 n · 실패 n · 보물 상자 +x · 사용 −x

### 3. 시즌
- 한 달이 한 시즌. 다음 달 1일 06:00 KST에 바뀐다. 남은 날은 `D = 그 달 마지막 날 − today의 일`이고, D-0은 "D-DAY"로 표시
- 시즌이 바뀌면 **전부 초기화**한다(NP 잔액 · 가방 · 밭 · 강화 · 탐험). 지난 시즌 도감 기록만 history에 남겨 홈 프로필에 표시
- 감지: `state.season ≠ season` → history에 `{ season, done, stars }`(§14)를 넣고 state를 새로 만든다
- 도감 6개 = 시드 `farm:{season}:codex`로 요리 100개(§13) 중 등급별로 고름: 일반 1 · 고급 2 · 희귀 2 · 전설 1 (§14). 시드 난수는 `mulberry32(hashString(str))`로, 시즌 내용이 모두에게 같다

### 4. 탐험
**쌓이는 시간** (1시간마다 r번 굴림, 상한 48h)
```
r        = 3 + 탐험 강화 단계(§7, 0~2)                    // 3 · 4 · 5번
쌓인 시간 = clamp(now − lastAt, 0, 48h)
h        = floor(쌓인 시간 / 1h)                         // 0~48
수령     → 1시간마다 r번 굴림, NP 상점 탐험 부스트(§15) 구간의 1시간은 2r번   // 부스트 없이 최대 144 · 192 · 240번
lastAt   ← (now − lastAt ≥ 48h) ? now : lastAt + h·1h    // 48h 넘긴 시간은 버리고, 1시간 안 된 나머지는 남김
```
- 시즌 첫 진입 때 `lastAt = 그 시각`. 시계가 뒤로 가면(`now < lastAt`) 쌓인 시간 0, `lastAt ← now`
- r은 **수령할 때**의 탐험 강화 단계로 센다. 강화를 만들기 전에 쌓인 시간도 새 r로 받는다

**굴림 1번**
```

2. 아니면     → 분류: 씨앗 60% · 자재 35% · 장비 5%
3. 분류 안    → 아래 %대로 1줄
4. 개수       → 그 줄의 범위에서 정수 균등
```

### 5. 농사 · 작물
- 모든 씨앗은 **8시간** 뒤 수확: `readyAt = plantedAt + 8h`
- 그림 단계: `p = (now − plantedAt) / 8h` → p < 0.15 씨앗 · < 0.5 새싹 · < 1 자람 · ≥ 1 다 큼. 다 큰 작물은 시들지 않는다
- 밭은 **2칸에서 시작해 최대 8칸**(§7 밭). 처음엔 **일반 씨앗만** 심을 수 있다(§7 시설 강화)

### 6. 품질
규칙: 0 없음(1~100) · 30까지 확률이 비슷 · 그 위로 부드럽게 감소 · 100 = 0.1%
```
p(k) = c                               1 ≤ k ≤ 30
p(k) = c · e^(−(k−30)² / (2σ²))        31 ≤ k ≤ 100
σ ≈ 30.06 (p(100) = 0.1%가 되게 이분법으로 풂),  c ≈ 1.5047% (합 = 1)
```

### 7. 제작 = 농장 강화 (39단계)
한 번 만들면 시즌 끝까지 유지되고 시즌이 바뀌면 초기화된다. 같은 줄은 번호 순서대로만 만든다.

| 줄 | 단계 | 효과 |
|---|---|---|
| 밭 | 1~6 | 단계마다 밭 +1칸 (2칸 → 8칸) |
| 씨앗 합성기 | – | 아래 등급 씨앗 10개 → 윗등급 1개. 항상 성공하고, 나온 씨앗은 §5 표대로 자람 |
| 효율 증대 | 1 · 2 · 3 | 합성 배율 9:1 · 8:1 · 7:1 |
| 정성스레 | 1 · 2 | 품질이 8 이하 · 16 이하면 한 번 다시 굴림 (8 이하 12.0% → 1.45%, 16 이하 24.1% → 5.8%) |
| 시설 강화 | 1 · 2 · 3 | 고급 · 희귀 · 전설 씨앗 심기 가능 |
| 풍작 | 1 · 2 | 일반 · 고급 작물 수확 때 50% 확률로 +1 |
| 풍작 | 3 · 5 | 풍작 1 · 2의 확률 → 100% |
| 풍작 | 4 | 희귀 작물 수확 때 25% 확률로 +1 |
| 풍작 | 7 · 11 · 14 | 풍작 4의 확률 → 50% · 75% · 100% |
| 풍작 | 6 · 13 | 일반·고급 작물 수확 때 50% 확률로 +1 (각자 따로 굴림) |
| 풍작 | 9 | 풍작 6의 확률 → 100% |
| 풍작 | 8 → 10 | 일반 작물 수확 때 전체 수확량 ×2, 확률 10% → 20% (판정은 한 번) |
| 풍작 | 12 → 15 | 고급 작물 수확 때 전체 수확량 ×1.5, 확률 10% → 20% (판정은 한 번) |
| 풍작 | 16 | 일반·고급·희귀 작물 수확 때 50% 확률로 +1 |
| 재사용 | 1 → 2 → 3 | 일반·고급 작물 수확 때 심었던 씨앗 1개 반환, 확률 10% → 20% → 30% |
| 재사용 | 4 | 희귀 작물 수확 때 심었던 씨앗 1개 반환 10% |
| 탐험 강화 | 1 · 2 | 탐험 1시간마다 굴림 +1 (3번 → 4번 → 5번, §4) |
| 장신구 착용 | 1 · 2 | 착용할 수 있는 장신구 +1개씩 (기본 1개 → 2 → 3개) |

**수확 개수** (더하기 다음 곱하기)
```
일반: 기본(2~3) + 풍작1 + 풍작6 + 풍작13 + 풍작16, 그다음 ×2 판정
고급: 기본(2~3) + 풍작2 + 풍작6 + 풍작13 + 풍작16, 그다음 ×1.5 판정 → 소수는 확률 반올림 (7.5 → 50%로 8, 50%로 7)
희귀: 기본(1~2) + 풍작4 + 풍작16
전설: 1
```
풍작을 다 만들면 평균: 일반 **6.6** · 고급 **6.05** · 희귀 **3.0** · 전설 **1**

**씨앗 합성**: 윗등급 1개 = 아래 등급 k개 (k = 10 → 효율 증대 뒤 9 · 8 · 7). 일반 → 전설 1개는 k=10이면 1,000개, k=7이면 343개

### 10. 저장 (localStorage)
- `daily-farm:state` = `{ v, season, attendance[], bonus, spent, sp, ap, money, inv{ seed[4], mat, mat2, crop{}, food{}, gear[], box, relic, ticket }, plots[{ seed, crop, plantedAt, readyAt } | null], built{ 줄 id: 단계 }, explore{ lastAt, boosts[[from, to]] }, shop{ day, bought{} }, equip[], codex{}, nextGear }`
  - `equip` = 착용 중인 장신구 id (최대 1 + 장신구 착용 단계)
  - 등급은 어디서나 0 일반 · 1 고급 · 2 희귀 · 3 전설. 씨앗은 등급별 개수 `seed[4]`, 작물은 개별 품질 배열(`inv.crop.<id> = [72, 45]`), 음식은 별 배열(`inv.food.<요리 번호> = [2, 0]`), 장신구는 `{ id, lines: [{ opt, tier, v }], lock }` (§11, id는 `nextGear`로 매김). `relic`은 아직 안 연 고대 유물 개수
- `daily-farm:history` = `[{ season, done, stars }]` (초기화 안 됨). `done` = 도감 등록 수(0~6), `stars` = 도감 별 합(0~18)
- 값이 깨졌으면 새 state를 만든다. localStorage가 막히면 메모리로만 동작한다(home.js `saveProfile`과 같은 방식)

### 11. 장신구 옵션
사용자가 정한 것: 장신구를 얻을 때 붙는 효과 수 **0~2줄**(0줄 50% · 1줄 40% · 2줄 10%), 효과마다 등급 **일반 60% · 고급 30% · 희귀 9% · 전설 1%**, 옵션마다 일반 · 고급 · 희귀 · 전설 수치, 고대 유물을 열면 **2줄이고 그중 1줄은 전설**인 장신구가 확정으로 나온다. 나온 장신구는 일반 장신구와 똑같다 (따로 구분하지 않음).
기름진 흙 삭제, 좋은 씨앗 · 돌연변이 너프도 사용자가 정했다. 나머지(옵션 9개 · 수치)는 Claude 추천이다. 입력 문서는 `docs/farm-gear.md`.

**굴림**
```
일반 장신구: 줄 수   → 0 (50%) · 1 (40%) · 2 (10%)
            줄마다 → 옵션 9개 중 균등 (한 장신구 안에서는 서로 다른 옵션)
                     등급 일반 60% · 고급 30% · 희귀 9% · 전설 1%
                     수치는 그 등급 범위에서 균등 (% 1 단위, %p 0.1 단위, 좋은 씨앗 · 돌연변이 0.5% 단위), 전설은 고정값
고대 유물 열기 (나오는 장신구):
            1줄째   → 옵션 균등, 전설 (고정값)
            2줄째   → 1줄째와 다른 옵션, 일반 장신구와 같은 등급 굴림 (60 · 30 · 9 · 1)
```
- 장신구 하나에 평균 0.6줄. 한 시즌 장신구 110~166개 → 66~100줄. 고대 유물 11~17개
- 한 시즌 희귀 줄 약 7~10 · 전설 줄 약 12~18 (고대 유물 11~17 + 일반 장신구 1%)

**착용 · 가방** (사용자)
- 착용 개수: **기본 1개**, 제작 장신구 착용 1 · 2로 **최대 3개**
- 같은 옵션을 여러 개 착용하면 수치를 **더한다**
- 장신구는 언제든 **바꿔 낄 수 있다**
- 장신구마다 **잠금**을 켜고 끌 수 있다. 잠근 장신구와 착용 중인 장신구는 분해할 수 없다
- 장신구 가방 한도 **100개** (착용 중인 것도 포함)
- **100개를 넘게 얻으면** (탐험 수령 · 고대 유물 열기) 얻는 그 자리에서 넘친 개수만큼 골라 AP로 만든다
  - 고를 수 있는 것: 잠그지 않았고 착용 중이 아닌 장신구 (방금 얻은 것 포함)
  - 얻기 전에는 100개 이하이고 방금 얻은 장신구는 잠금 · 착용이 아니라서, 고를 장신구가 모자라는 일은 없다
  - 구현: 얻은 장신구를 먼저 가방에 넣고 저장한 뒤, 100개가 넘으면 고르기 판을 띄운다. 100개 이하가 될 때까지 판이 닫히지 않고, 새로고침해도 다시 뜬다
  - 한 번에 많이 넘칠 수 있다: 48시간 수령이면 장신구 약 7 ~ 12개
- 한 장신구에 같은 옵션은 두 줄 붙지 않으니, 같은 옵션은 최대 3줄(전설이면 ×3)까지 더해진다. 그래도 100%를 넘는 옵션은 없다: 풍년 · 합성 대성공 · 주머니 최대 90%, 씨앗 되받기 60%, 서두르기 30%, 좋은 씨앗 · 돌연변이 18%, 보물 감각 +3%p

**옵션 9개** (수치 단계 = 일반은 전설의 1/3까지 · 고급 2/3까지 · 희귀 5/6까지 · 전설 고정)
| 분류 | 옵션 | 효과 | 일반 | 고급 | 희귀 | 전설 |
|---|---|---|---|---|---|---|
| 탐험 | 씨앗 주머니 | 탐험에서 나오는 씨앗 개수 +x% | 1~10% | 11~20% | 21~25% | 30% |
| 탐험 | 자재 주머니 | 탐험에서 나오는 자재 · 고급 자재 개수 +x% | 1~10% | 11~20% | 21~25% | 30% |
| 탐험 | 보물 감각 | 탐험 히든 확률 +x%p (기본 1%) | 0.1~0.3%p | 0.4~0.6%p | 0.7~0.8%p | 1.0%p |
| 탐험 | 좋은 씨앗 | 탐험에서 씨앗이 나올 때 x% 확률로 한 등급 위 씨앗 (개수는 바뀐 등급 범위로, 전설은 그대로) | 0.5~2% | 2.5~4% | 4.5~5% | 6% |
| 농사 | 풍년 | 수확할 때 x% 확률로 +1개 (모든 등급) | 1~10% | 11~20% | 21~25% | 30% |
| 농사 | 씨앗 되받기 | 수확할 때 x% 확률로 심었던 씨앗 1개 반환 (모든 등급) | 1~6% | 7~13% | 14~16% | 20% |
| 농사 | 돌연변이 | 심을 때 x% 확률로 작물 등급 한 단계 위 (전설은 그대로) | 0.5~2% | 2.5~4% | 4.5~5% | 6% |
| 제작 | 합성 대성공 | 씨앗 합성 때 x% 확률로 2개 | 1~10% | 11~20% | 21~25% | 30% |
| 기타 | 서두르기 | 수확할 때 x% 확률로 농사 즉시 완료권 1장 | 1~3% | 4~6% | 7~8% | 10% |

- 씨앗 · 자재 개수 +x%의 소수는 확률 반올림한다 (§7 고급 ×1.5와 같은 방법)
- 적용 순서: 풍년은 §7 수확 개수의 더하기 단계에 넣는다
- 좋은 씨앗 · 돌연변이 너프 15% → 6%: 좋은 씨앗 전설 1줄이면 하루 전설 씨앗 0.64 → 1.51개였는데, 이제 0.99개
- 뺀 것:
  - 기름진 흙 (사용자 삭제)
  - 성장 시간 · 탐험 상한: 8시간 · 48시간 고정 규칙 때문에
  - 데일리 NP: `earned`를 기록에서 매번 다시 계산해서, 장신구로 늘리면 장신구를 바꿀 때 지난 NP도 바뀐다
  - 요리: 요리가 정해지면 옵션을 더 넣는다

### 12. 화폐 · 분해 · 판매
사용자가 정한 것 (10/5): 남는 것을 분해 · 판매해 화폐로 바꾸고, **NP · SP · AP는 상점에서, 돈은 제작(§8)에 쓴다** (돈 상점은 10/5에 없앰).

| 화폐 | 얻는 곳 | 쓰는 곳 |
|---|---|---|
| NP | 출석 · 데일리 결과(§2) · 보물 상자 | NP 상점 |
| SP | **씨앗 분해** | SP 상점 |
| AP | **장신구 분해** (남는 장신구 처리) | AP 상점 |
| 돈 | **음식 판매** (요리 결과물) | 제작 (§8) |

- 다른 것과 같이 시즌이 바뀌면 초기화한다 (§3). NP는 지금처럼 `earned + bonus − spent`, SP · AP · 돈은 잔액만 저장한다
- 음식 판매 값은 §14 (원래 값 × 별 배율 ×1 · ×5 · ×30 · ×200). 상점은 §15. 입력 문서 `docs/farm-shop.md`

**분해 값** (사용자)
```
씨앗 1개 → SP: 일반 1 · 고급 3 · 희귀 15 · 전설 100
장신구 1개 → AP = 1 + Σ(효과 줄마다 등급 값)    등급 값: 일반 2 · 고급 5 · 희귀 20 · 전설 50
```
- 착용 중인 장신구와 잠근 장신구는 분해할 수 없다 (사용자)
- 장신구 예: 효과 0줄 = 1 · 고급 1줄 = 6 · 고대 유물에서 나온 전설 + 희귀 = 71
- 평균: 효과 1줄의 등급 값 5.0 → 탐험 장신구 1개 4.0 AP · 고대 유물 장신구 1개 56 AP
- 하루 (72번 ~ 120번, 모두 분해했을 때): SP 494 ~ 823 · AP 34 ~ 57
- 한 시즌 (모두 분해했을 때): SP 15,300 ~ 23,100 · AP 1,070 ~ 1,610 (그중 고대 유물 장신구가 625 ~ 941). 심은 씨앗과 착용한 장신구만큼 줄어든다
- 합성과 비교: 씨앗을 SP로 바꿀 때는 합성보다 아래 등급 그대로 분해하는 게 늘 많다 (일반 10개 = 10 SP > 고급 1개 = 3 SP, 효율 증대 3의 7:1이어도 7 > 3 · 21 > 15 · 105 > 100). 합성은 심을 씨앗을 만드는 데만 쓰인다

**한 시즌에 들어오는 양** (탐험 강화 없음 ~ 5일 · 10일에 만든 기준)

|---|---|---|
| 일반 씨앗 | 3,180 ~ 4,790 | 103 ~ 171 |
| 고급 씨앗 | 1,590 ~ 2,400 | 51 ~ 86 |
| 희귀 씨앗 | 358 ~ 539 | 11.5 ~ 19 |
| 전설 씨앗 | 20 ~ 30 | 0.64 ~ 1.1 |
| 장신구 (절반은 효과 0줄) | 110 ~ 166 | 3.6 ~ 5.9 |
| 고대 유물 | 11 ~ 17 | 0.36 ~ 0.6 |

### 13. 요리 목록 (100개)

### 14. 요리하기 · 별 · 판매 · 도감
사용자가 정한 것 (10/5):
- 레시피 100개(§13)는 처음부터 다 주어진다. 요리 = **레시피 고르기 → 가방에서 재료 작물 고르기 → 요리**. 같은 작물이라도 품질이 하나씩 달라서 어떤 걸 넣을지 고른다
- 별 굴림 (10/5 Claude 추천안으로 확정. 처음 안이었던 "15% + 최대 15 소모" 룰렛은 품질과 상관없이 70% 이상이 0성이라 바꿈)
```
평균 품질 = 재료 작물 품질의 합 ÷ 재료 개수                    예: (30 + 50 + 50 + 70) ÷ 4 = 50
k번째 룰렛 성공 확률 = 평균 품질 − 등급 감점 − 25 × (k − 1)   (5% ~ 95%로 자름)
등급 감점: 일반 0 · 고급 5 · 희귀 10 · 전설 15
실패할 때까지 돌리고, 성공 횟수가 별 (최대 3성, 3번 성공하면 멈춤)
예 (일반, 평균 품질 78): 78% → 53% → 28%
```
- 판매 값(돈) = 요리마다 **원래 값 × 별 배율**: 0성 ×1 · 1성 ×5 · 2성 ×30 · 3성 ×200
- 원래 값 = **요리 등급 기본 가격 × (0.9 ~ 1.1 랜덤)**
- 등급 기본 가격 (Claude 추천, 10/5 사용자 요청): **일반 10 · 고급 30 · 희귀 150 · 전설 1,000** → 원래 값 9~11 · 27~33 · 135~165 · 900~1,100
  - 씨앗 분해 SP와 같은 비율(1 · 3 · 15 · 100)에 ×10. 작물을 얻는 데 드는 씨앗의 값어치만큼 요리 값이 오르고, ×10이라 ±10%가 정수로 드러난다
  - 3성이면 원래 값 ×200: 일반 1,800~2,200 · 전설 18만~22만 돈. 제작 돈 비용(§8)은 이 크기로 어림한 돈 수입에 맞췄다
- 도감 6개 = 시즌마다 시드 `farm:{season}:codex`로 등급별 랜덤: **일반 1 · 고급 2 · 희귀 2 · 전설 1**
- 도감 등록 = 그 요리를 **제출**한다 (가방에서 없어짐). 이미 등록한 요리도 **별이 더 높은 걸 내면 갱신**된다
- 요리는 먹지 않는다. 쓰는 곳은 판매(돈)와 도감 제출뿐

Claude가 정한 것 (구현):
- 요리 등급 = §13의 등급 (재료 중 가장 높은 작물 등급)
- 평균 품질은 소수 그대로 쓴다 (예: 50.67)
- 원래 값의 ±10%는 **요리마다 한 번 정해 고정**한다. 시드 `farm:price:{요리 id}`라 모두에게 같고 시즌이 바뀌어도 같다. 정수로 반올림
- 도감 제출은 처음이거나 지금 기록보다 별이 높을 때만 버튼이 켜진다 (같거나 낮은 걸 내서 날리는 일이 없게). 0성도 처음 등록은 된다
- 도감 기록: `codex = { <요리 id>: 별 }`. 시즌이 끝나면 history에 `done` = 등록 수(0~6), `stars` = 별 합(0~18)을 남긴다
- 음식은 가방에 별 배열로 저장한다: `inv.food.<id> = [2, 0, 1]` (값은 요리와 별로 계산하니 따로 저장 안 함)

**계산 결과** (재료 평균 품질별. 0성 / 1성 / 2성 / 3성 %, 기대 배율 = 원래 값의 몇 배로 팔리는지)
| 요리 등급 | 품질 36 | 품질 62 | 품질 78 | 품질 90 |
|---|---|---|---|---|
| 일반 | 64/32/4/0 · ×3.8 | 38/39/20/3 · ×13.9 | 22/37/30/12 · ×34.1 | 10/32/35/23 · ×59.0 |
| 고급 | 69/29/2/0 · ×2.9 | 43/39/17/1 · ×10.0 | 27/38/27/8 · ×26.4 | 15/34/33/18 · ×47.5 |
| 희귀 | 74/25/1/0 · ×2.5 | 48/38/13/1 · ×7.8 | 32/39/24/5 · ×20.0 | 20/36/31/13 · ×37.6 |
| 전설 | 79/20/1/0 · ×2.2 | 53/37/10/1 · ×6.3 | 37/39/21/3 · ×14.8 | 25/38/28/9 · ×29.3 |

- 첫 룰렛 확률이 곧 재료 품질이라 품질에 비례하는 게 보인다. 아무 재료나 넣으면 대부분 0~1성, 좋은 재료를 고르면 2~3성
- 좋은 재료를 쓴 요리는 원래 값의 30~60배로 팔린다 (3성 ×200 때문). 등급 기본 가격과 상점 값을 정할 때 같이 본다

**재료 품질을 올리는 방법** (지금 있는 것)
- **고르기**: 요리할 때 재료를 고르니, 같은 작물을 많이 가질수록 좋은 것만 쓸 수 있다. 같은 작물 n개 중 가장 좋은 3개의 평균 품질: 3개 36 · 10개 62 · 30개 78 · 100개 89
- **정성스레 1 · 2** (제작): 8 이하 · 16 이하면 한 번 다시 굴림. 작물 평균 36.2 → 42.8. 많이 가진 작물에서는 효과가 작다 (10개 중 3개 62 → 66, 30개 중 3개 78 → 80)
- 일반 작물은 많이 들어와서 쉽게 70~90이 되고, 희귀 · 전설 작물은 적어서 고를 게 별로 없다

### 15. 상점
사용자가 정한 것 (10/5): 화폐별로 **AP · SP · NP 상점** 3개 (돈 상점은 10/5에 없앰). 한도는 **매일 리셋** (06:00 KST, `todayStr`이 바뀔 때). 매일 랜덤으로 **AP 상점 2개 · SP 상점 2개**. **AP 상점과 SP 상점은 같은 상품 리스트**에서 뽑고 **SP 값 = AP 값 × 10**. AP · SP 상품은 아래 7개 (사용자).

- 산 시각부터 8시간. 이미 켜져 있으면 끝나는 시각에 8시간을 이어 붙인다 (겹쳐서 ×4가 되지 않음). 하루 3개면 최대 24시간
- 사기 전에 쌓인 시간은 그대로 (지나간 시간에는 안 붙음)
- 수령할 때 1시간 단위로 센다: 그 1시간이 시작한 시각이 부스트 구간 안이면 2r번. 구간은 `explore.boosts = [[from, to], ...]`로 저장하고 48시간 지난 건 지운다
- 산 개수는 `shop = { day, bought: { "np:boost", "ap:mat", "sp:seed2", ... } }`. `day`가 오늘이 아니면 0부터

**값 크기**
- 부스트 1개 = 굴림 24 ~ 40번 더 (탐험 강화 0 ~ 2단계). 하루 72 ~ 120번의 1/3
- 다 사면 하루 24 NP (부스트 18 + 완료권 6). 하루 NP 수입은 출석 · 데일리 최대 32 + 보물 상자 평균 22 ~ 36
- 시즌에 NP를 쓰는 곳은 지금 이 둘뿐 (최대 31일 × 24 = 744 NP)
